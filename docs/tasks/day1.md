# **День 1\. Создаём работающую основу**

Цель дня: К концу дня плагин запускается в IntelliJ IDEA, отображает утку и позволяет переключать ее состояния.

### **Участник 1 — Plugin Developer**

| Задача | Описание задачи | Definition of Done |
| ----- | ----- | ----- |
| 1\. Создать болванку плагина | Создать проект на Kotlin с использованием IntelliJ Platform Plugin SDK. Настроить Gradle, конфигурацию запуска IDE и структуру проекта. | Проект собирается, тестовая IntelliJ IDEA запускается с установленным плагином. |
| 2\. Создать окно питомца | Добавить Tool Window или другую согласованную область IDE, в которой будет отображаться утка. | После запуска IDE доступно окно с заглушкой питомца. Окно не ломает интерфейс IDE. |
| 3\. Подготовить отображение анимаций | Реализовать компонент, который умеет отображать изображение утки в зависимости от ее состояния. На первом этапе можно использовать обычные PNG-картинки вместо полноценной анимации. | Для каждого из четырёх состояний можно передать соответствующую картинку, и она отображается в окне питомца. |

### **Участник 2 — Duck Logic Developer**

| Задача | Описание задачи | Definition of Done |
| ----- | ----- | ----- |
| 1\. Реализовать модель питомца | Определить основные состояния (`IDLE`, `WORKING`) и предусмотреть возможность добавления `HAPPY`, `SAD`, `SLEEPING`. Создать модель состояния питомца.  | Состояния и переходы описаны в коде. Добавление нового состояния не требует изменения всей логики питомца.  |
| 2\. Реализовать обработку событий | Создать компонент, который принимает события и на их основе меняет состояние утки. Например, событие активности переводит её в `WORKING`.  | Состояние меняется при получении соответствующих тестовых событий.  |
| 3\. Подготовить мотивационные фразы | Составить список коротких мотивационных фраз и сообщений для взаимодействия с уткой. Реализовать выбор случайного сообщения.  | Можно запросить случайную фразу из заранее подготовленного набора.  |

### **Участник 3 — Integration & Persistence Developer**

| Задача | Описание задачи | Definition of Done |
| ----- | ----- | ----- |
| 1\. Согласовать контракты компонентов | Определить общие модели событий, состояния питомца и способы передачи обновлений.  | Участники используют единые классы и интерфейсы, компоненты могут взаимодействовать друг с другом.  |
| 2\. Реализовать сохранение состояния  | Изучить `PersistentStateComponent` и создать компонент для хранения состояния питомца и количества введенных символов.  | Данные можно сохранить и восстановить через отдельный компонент.  |
| 3\. Подготовить сценарии проверки  | Описать основные сценарии: запуск плагина, активность, бездействие, возвращение пользователя, взаимодействие с уткой и перезапуск IDE.  | Есть список сценариев, по которому команда сможет проверить готовый MVP.  |

В конце дня: соединить отображение питомца с моделью состояния. Например, при тестовом событии активности утка должна переключаться с `IDLE` на `WORKING`.
