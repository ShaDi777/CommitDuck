## **День 3\. Дополнительные возможности**

Идем по приоритетам и останавливаемся, если времени не хватает.

### **Участник 1 — Plugin Developer**

| Задача | Описание задачи | Definition of Done |
| ----- | ----- | ----- |
| 1\. Подключить Git-события | Изучить доступные механизмы IntelliJ Platform для получения информации о Git-коммитах. Реализовать реакцию на создание коммита. | После успешного коммита плагин получает событие и может передать его логике питомца. |
| 2\. Подготовить интерфейс Debug Duck  | Добавить отдельную область или диалог для общения с уткой. Предусмотреть поле ввода сообщения и область отображения диалога.  | Пользователь может открыть Debug Duck, ввести сообщение и увидеть ответ-заглушку.  |
| 3\. Подключить интерфейс к обработке диалога  | Связать UI с компонентом обработки сообщений. Обеспечить отображение истории диалога.  | Сообщения пользователя и ответы утки отображаются последовательно.  |

### 

### **Участник 2 — Duck Logic Developer**

| Задача | Описание задачи | Definition of Done |
| ----- | ----- | ----- |
| 1\. Реализовать реакцию на коммит | Добавить обработку события успешного коммита. Утка должна радоваться завершению работы и показывать соответствующее сообщение.  | При получении Git-события утка переходит в радостное состояние и показывает сообщение.  |
| 2\. Реализовать базовый Debug Duck  | Подготовить набор обобщённых наводящих вопросов, которые помогают разработчику разобраться в проблеме. Реализовать простую логику выбора вопроса.  | Пользователь может начать диалог, а утка задаёт вопросы из подготовленного набора.  |
| 3\. Подготовить сценарий общения с LLM  | Определить системный промпт и формат запроса к модели. Утка должна выступать в роли помощника, который задаёт наводящие вопросы, а не сразу выдаёт готовое решение.  | Подготовлен и проверен сценарий диалога с несколькими последовательными сообщениями.  |

### 

### **Участник 3 — Integration & Persistence Developer**

| Задача | Описание задачи | Definition of Done |
| ----- | ----- | ----- |
| 1\. Реализовать клиент для LLM API  | Подключить выбранный API языковой модели. Реализовать отправку сообщений и получение ответов.  | Плагин может отправить запрос к модели и получить текстовый ответ.  |
| 2\. Подключить LLM к Debug Duck  | Связать клиент LLM с интерфейсом диалога и логикой Debug Duck. Передавать историю диалога, чтобы ответы учитывали предыдущие сообщения.  | Пользователь может вести последовательный диалог, а ответы модели учитывают контекст беседы.  |
| 3\. Добавить обработку ошибок LLM  | Предусмотреть ситуации, когда API недоступно, запрос завершается ошибкой или превышено время ожидания. Добавить понятное сообщение пользователю.  | При ошибке плагин не зависает и показывает понятное уведомление.  |
| 4\. Подготовить конфигурацию API  | Вынести адрес API и настройки модели в конфигурацию. Не хранить API-ключ непосредственно в исходном коде.  | Для подключения модели не требуется изменять исходный код или пересобирать плагин.  |
